## Git
- `main` is the stable branch.
- Each team member works on their own branch.
- Do not make changes directly on `main`.
- Make small, focused commits.
- Do not commit secrets, API keys, passwords, or `.env` files.

## Development
- Inspect the existing project before making architectural decisions.
- Prefer simple solutions suitable for an MVP.
- Do not add dependencies unless they are necessary.
- Run tests/lint/build after significant changes.

## Codex
Before implementing a large feature:
1. Inspect the relevant files.
2. Explain the proposed approach.
3. Implement incrementally.
4. Test the implementation.
5. Summarize what changed and any remaining issues.
